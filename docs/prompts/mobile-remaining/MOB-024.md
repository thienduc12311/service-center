# MOB-024 — Plan rehearsal player and background audio

Read [execution rules](../IMPLEMENTATION-RULES.md). **User story:** As a musician, I rehearse the plan's permitted tracks in order while reading the correct chart, with coherent transport and background controls.

**Read:** mobile spec rehearsal section; US-14.1; [F13](../services-capabilities/F13.md) files and [F14](../services-capabilities/F14.md) manifest/player prompts; native plan/song screens; shared chart resolver and API client; existing web RehearseTab. Current chart reading is not audio playback.

## Pass A — Manifest and native adapter

1. Reuse/implement F13 authorized versioned files and F14 ordered rehearsal manifest, including plan item, arrangement, effective key/sequence, media type, stream/download rights and expiry. Avoid embedding long-lived secret URLs in caches. **Done:** unauthorized files are absent and manifest order matches the running order.
2. Verify current official Expo/native audio/video documentation and development-build requirements before choosing an adapter compatible with the installed runtime. Define one typed playback state machine for loading/ready/playing/paused/ended/error. **Done:** supported formats, external-link fallback, interruption behavior and build needs are documented and exercised with local permitted fixtures.

## Pass B — Player UI and audio session

3. Add track selection, play/pause/seek, previous/next, repeat and a mini-player backed by one playback owner. Show effective chart/key/tempo without suggesting the audio is transposed unless it actually is. Video is an explicit foreground player; unsupported provider links open externally. **Done:** navigation cannot start duplicate players or misleading key-shifted audio.
4. Configure supported background audio/lock-screen media controls and audio-focus interruption policy. Reconcile state from the adapter after app backgrounding, phone/headphone interruption and remote controls. **Done:** UI, sound and lock-screen metadata agree on a real supported build.
5. On sign-out or lost authorization, stop playback and clear private metadata; organization switching must not silently continue an undisclosed prior-org playlist. Document the explicit policy for staying on or ending a selected playlist. Renew expired streams under current access. **Done:** stale private tracks cannot restart from an old cache or control intent.
6. Test track failure/skip, expiry, seek bounds, repeat/end, interruption, navigation, account switch and unsupported link. Run common checks and physical iOS/Android foreground/background tests. **Done:** test reports distinguish export success from verified audio-session behavior.

**Acceptance:** ordered permitted playback, correct chart context, single coherent player, truthful external/unsupported states and supported interruption/background handling. Offline packs and audio transforms follow separate tasks.

**Handoff:** chosen adapter/documentation, supported formats/builds, playback policy and remaining real-device gates.
