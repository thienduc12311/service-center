# MOB-028 — Paginated song library and metadata authoring

Read [execution rules](../IMPLEMENTATION-RULES.md). **User story:** As a planner, I find songs beyond the first page, edit their arrangements and metadata, and preserve the history of archived material.

**Read:** mobile spec song authoring section; US-15.1/15.3; [F15 prompt](../services-capabilities/F15.md); native songs/song screens; website SongsPage, SongDetailPage and arrangement components; backend song routes/services; shared song schemas/client and chart context from MOB-002.

## Pass A — Existing API breadth

1. Inspect current list caps, sort/filter/cursor contracts and capabilities. Add bounded stable pagination if absent and expose supported title/theme/sort filters. Preserve query context by account/org/filter. **Done:** a fixture above 100 songs can be fully browsed without duplicates/skipped rows or unauthorized results.
2. Add permitted song/arrangement create/edit using current metadata: title, authors/copyright fields, tags, tempo/meter, key/capo, default and sequence as actually supported. Reuse shared validation and explicit revision handling. **Done:** saved changes reload on web and defaults remain valid when an arrangement changes.
3. Preserve unsaved drafts, distinguish library edits from plan-specific viewing overrides and handle deleted/default arrangement conflicts. Require deliberate destructive actions; historical references cannot disappear accidentally. **Done:** saving library metadata never silently overwrites another plan's key/sequence.

## Pass B — Curation and labeled keys

4. Reuse/implement selected F15 filter/archive/key stages before exposing author/key/BPM/history filters, archive/restore or multiple labeled keys. One current arrangement key is not a multi-key model. Keep archived records out of normal pickers but available in historical plan reading. **Done:** native controls correspond to real persisted contracts and restore preserves references.
5. Add scoped scheduled-history display with supported filters and pagination. Connect labeled keys/files through F15/F13 when available; provider import requires an explicitly selected F17 adapter. **Done:** history identifies actual plans and authorized key/file versions without implying unbuilt provider access.
6. Test more-than-one-page browsing, equal-title sort, concurrent edits, default deletion, archive/history, wrong-org arrangement and invalid key/tempo. Run common checks and native picker/form accessibility review. **Done:** shared validation, server authority and visible library state agree.

**Acceptance:** pagination beyond 100, authorized metadata/arrangement editing, valid defaults, draft recovery, historical integrity and truthful optional feature gates.

**Handoff:** completed pass, filters/contracts supported, archive/key prerequisites and exact validation results. Native chart source editing belongs to MOB-029.
