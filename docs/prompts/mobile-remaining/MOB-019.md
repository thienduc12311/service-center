# MOB-019 — Scoped conversations and message history

Read [execution rules](../IMPLEMENTATION-RULES.md). **User story:** As a team member, I follow permitted plan/team discussions, receive useful mentions and safely retry a failed message.

**Read:** mobile spec chat section; US-09.3; [F09 prompt](../services-capabilities/F09.md) conversation pass; F01 access/F13 files; native notifications/plan workspace; backend notification center, shared schemas/client and current query conventions. A notification feed is not a conversation service.

## Pass A — Shared conversations

1. Verify/implement F09 conversation, membership, message, read-state, mute and moderation contracts. Use stable client message IDs, pagination, allowed content and server timestamps. Define team/group limits and retention. Team membership changes reauthorize future reads/posts and realtime subscriptions. **Done:** API/RLS tests prevent private-history enumeration and an old subscription cannot continue delivering revoked content.
2. Establish the actual organizational youth/guardian policy before enabling communication branches that need it. Default to policy-approved scoped operational threads; keep direct messages/rich social features gated until supported. Do not infer policy from conflicting reference age wording. **Done:** enabled conversation types have enforceable membership/moderation rules, not a cosmetic age label.

## Pass B — Native thread experience

3. Add a conversation entry and paginated list/detail under the appropriate team/plan context. Render safe text, replies/mentions and unread markers only for implemented contracts. Keep loading, empty, removed-membership and unavailable-thread states explicit. **Done:** navigation resolves a permitted conversation in the active organization.
4. Add composer draft, send/retry/cancel states keyed by stable message identity. Reconcile acknowledgement/realtime events without duplicate bubbles; preserve draft on failure. Advance read state from actual visible history and support mute separately from OS push permission. **Done:** reconnect yields one message per identity and unread state agrees with server history.
5. Route mention/thread push through validated MOB-003 intents and MOB-020 preferences. Attach files only through F13 authorization; moderation/report actions use the F09 policy. Live chat reuses the same transport with run scope, not another chat backend. **Done:** notification snippets, uploads and subscriptions obey conversation access.
6. Test duplicated send, lost acknowledgement, pagination overlap, revoked member, muted thread, malicious text, denied attachment and org change. Run shared/backend/RLS/native checks; record foreground/background device checks separately. **Done:** history, retries and privacy hold under reconnect.

**Acceptance:** authorized paginated chat, idempotent send, truthful unread/mute, revocation, safe content and actual moderation path. DMs/read receipts/GIFs remain separately gated extensions.

**Handoff:** enabled conversation types/policy, shared contracts, reconnect evidence and remaining device or policy gates.
