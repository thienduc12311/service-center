# MOB-017 — Mark actual attendance by plan time

Read [execution rules](../IMPLEMENTATION-RULES.md). **User story:** As an authorized team leader, I record who actually attended a service or rehearsal and correct mistakes with a visible history.

**Read:** mobile spec MOB-017; US-16.1; [F16 prompt](../services-capabilities/F16.md) attendance pass; F04 assigned-time resolver; native plan Teams screen; shared assignment/Person/time types; existing calendar and staffing routes.

## Pass A — Attendance contract

1. Verify/reuse F16 attendance persistence and API. If absent, implement that bounded pass first. Records identify organization, Person and actual plan-time occurrence; states are present/absent/unknown, independent of assignment answers. Keep author/time/reason and correction history. **Done:** a confirmed assignment creates no automatic “present” record.
2. Enforce team/plan/time capability and actual roster eligibility; deduplicate a Person appearing in multiple positions at one occurrence. Use expected version and idempotency for reviewed batch changes, with atomic declared scope. **Done:** API/direct SQL tests deny another team's updates and duplicate role rows cannot double-count attendance.

## Pass B — Native marking

3. Add an Attendance entry in the permitted plan workspace. Select time and team, show applicable scheduled Persons and current marks, and distinguish “unknown/not recorded” from “absent.” Retain position context without duplicate Person controls. **Done:** the selected occurrence and scope are explicit in every row and batch review.
4. Support individual marking and a reviewed batch listing exact people/time/state. Preserve unsaved selection on failure and avoid showing optimistic marks as saved. Add a correction flow with reason and previous value; show allowed history. **Done:** a stale batch refreshes rather than overwriting newer marks and retry uses the original operation identity.
5. Refresh attendance/report queries without changing schedule confirmation. Handle removed/archived people through historical identity and revoked leadership through denied states. **Done:** web/report reload agrees and original assignment answers remain intact.
6. Test multiple positions, two service occurrences, rehearsal, unknown versus absent, unauthorized team, correction, concurrent leaders and failed batch rollback. Run backend/RLS and common native checks; inspect large text and batch review accessibility. **Done:** final counts reconcile to unique Person/occurrence records and audit authors.

**Acceptance:** actual attendance is distinct from scheduling, occurrence identity is stable, corrections are audited, batches are truthful/atomic and historical records survive archive.

**Handoff:** contracts reused/added, metric definitions, concurrent-write evidence and remaining device gates. Check-Ins import stays an optional F17 adapter.
