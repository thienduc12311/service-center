# MOB-032 — Opted-in combined schedule for own organizations

Read [execution rules](../IMPLEMENTATION-RULES.md). **User story:** As someone serving in several organizations, I deliberately combine my own commitments while keeping each organization's actions and private information separate.

**Read:** mobile spec aggregate organizations section; US-03.4; [F03 prompt](../services-capabilities/F03.md) aggregate pass; MOB-003 session/context implementation; native schedule/calendar/AuthProvider; shared schedule API and organization membership validation.

## Steps

1. Verify explicit opt-in and current linked Person membership in each selected organization. Implement/reuse F03 self-only aggregation; it is not an organization-wide cross-tenant search. Define canonical occurrence identity including org ID, per-org timezone label and partial-failure behavior. **Done:** only the current person's accessible commitments are eligible for aggregation.
2. Use immutable per-request organization context. Do not switch a shared global API organization repeatedly while launching concurrent fetches. Bound selected organizations, date ranges and pagination. **Done:** simultaneous requests are demonstrably sent with the correct identity/org pair and cannot cross-populate caches.
3. Add opted-in selection, combined schedule/agenda and clear organization labels. Distinguish incomplete organization results from an empty schedule; render dates in an explicit display timezone while preserving each event's original zone details. **Done:** sorting and grouping remain correct across timezones and DST without dropping failed-org warnings.
4. Open actions in the actual owning organization only after reauthorization. Response/availability/signup/delegation rights remain separately checked there. Any cross-organization conflict returned to another scheduler is a generic blocked interval, never another organization's title, people or notes. **Done:** a combined view grants no new plan/directory permission.
5. Handle removed membership, logout/account change, selected-org revocation and late responses by clearing only the appropriate private scope. If availability copying is offered, require explicit source/targets and a separate authorized commit per declared operation. **Done:** neither old membership nor selection survives as authority.
6. Test two organizations with overlapping IDs/times, three timezones, one failed response, revoked membership, response after context switch and redacted conflict output. Run shared/backend/native checks and visual context review. **Done:** combined rows and underlying operations reconcile to each organization independently.

**Acceptance:** opt-in own-data aggregation, reliable context isolation, explicit partial failure/timezone behavior and per-org reauthorization. Household aggregation is not implied by self access.

**Handoff:** aggregate API/context strategy, privacy tests, display-timezone policy and remaining device gates.
