# MOB-011 — Household picker and delegated actions

Read [execution rules](../IMPLEMENTATION-RULES.md). **User story:** As an explicitly authorized helper, I manage another household member's schedule or availability without receiving unrelated access to their private plans and files.

**Read:** mobile spec MOB-011; Services F03; US-03.3; [F03 prompt](../services-capabilities/F03.md). Inspect `mobile/src/providers/AuthProvider.tsx`, native schedule/calendar/profile/plan screens, shared Person/schedule contracts, and backend people/assignment/blockout routes. No household grant API is assumed to exist.

## Pass A — Explicit delegation contract

1. Verify Person identity, versioned responses, availability and signup prerequisites. Implement F03's delegation pass if absent. Persist grantor, delegate, target Person, organization, permitted actions, expiry/revocation and audit. An adult approves their own grant; household relationship alone grants nothing. For minors, require an established organizational guardian policy; keep that branch disabled until supplied. **Done:** API and RLS tests deny an ungranted adult action and distinguish respond, view-plan, availability and signup rights.
2. Provide a real grant review/revoke entry through the supported settings surface, with the narrowest safe default actions. Revalidate actor membership, target Person and current grant/version at commit and download renewal. **Done:** a grant can be issued and revoked without direct DB edits, and revocation blocks subsequent actions.

## Pass B — Native person context

3. Add a “Viewing schedule for” picker containing self and explicitly permitted Persons. Scope queries, drafts, mutation IDs and saved navigation by actor, organization and selected Person. Reset selected Person on logout, org change or revoked grant. **Done:** delayed results for one Person never render under another person's name.
4. Reuse response, blockout and signup screens only for individually authorized actions. A response grant may show the minimal request without granting plan or attachment access. Preview names, exact positions/times and acting-on-behalf identity before submission. **Done:** each action's review matches its server-authorized scope and audit identifies the real actor.
5. Test revoke-after-preview, expired grant, two adults, changed organization, missing view-plan right, disabled signup right and response retry. Use canonical request/capacity transactions rather than a delegated alternative implementation. **Done:** forbidden controls are absent and forged direct calls still fail; state/error screens remain truthful.

**Acceptance:** explicit consent, independent rights, no private plan/file escalation, atomic scoped responses and no cross-Person cache leakage. Shared/backend/RLS checks and native export pass; adult/minor policy and device gates are documented separately.

**Handoff:** grant semantics, permission matrix, tested cases, selected native actions and remaining gates. General household management is not automatically complete because the picker works.
