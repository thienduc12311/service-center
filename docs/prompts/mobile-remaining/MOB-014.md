# MOB-014 — Edit and reorder the native running order

Read [execution rules](../IMPLEMENTATION-RULES.md). **User story:** As a planner, I add or edit an item, choose the correct song arrangement/key and move it without overwriting another planner's work.

**Read:** mobile spec planning section; US-11.1/11.2/11.3; [F11 prompt](../services-capabilities/F11.md); native plan/song screens and MOB-002 resolver; web `OrderTab.tsx`, `AddItemModal.tsx`; backend plan item/order endpoints; shared plan/song schemas and chart renderer.

## Pass A — Ordinary item CRUD and order

1. Inventory existing item create/update/delete/reorder contracts. Add expected plan revision and an atomic reorder operation if missing. Validate full ordered-ID membership, duplicates, plan ownership and compatible song/arrangement/key references. **Done:** a stale editor receives a conflict rather than overwriting a newer order.
2. Add native add/edit sheets for song, header and free-form item, using existing field names: title, length, description, arrangement and service key. Show song choices with bounded search and loading. Preserve draft and stable item identity through edit/retry. **Done:** saved edits reload identically on web, with no mutation to library defaults.
3. Add move-up/down controls, optional drag as a supplement, and deliberate remove review. Commit reorder once; on failure restore the server-consistent order and explain stale changes. **Done:** keyboard/screen-reader users can perform every move and a failed mutation does not leave a fictitious order.

## Pass B — Sequence and supported responsibility fields

4. Reuse MOB-002/F11's persisted item-specific sequence and shared validation. Expose section selection/sequence controls that inherit the arrangement when unset. Add item leader/category/applicability only after the named F11/F09 contracts exist; implement missing selected slices rather than local-only fields. **Done:** sequence edits affect this item only and every displayed control has persisted behavior.
5. Use the canonical effective-key/sequence resolver in order preview, rehearsal and chart links. Headers consume zero scheduled time. Show computed duration/time output when F11 supports it, without storing redundant timestamps in native. **Done:** labels, chart chords and running-order output agree after edits.
6. Test incompatible arrangement, two simultaneous edits, reordered/deleted item, timeout retry, large order, duplicate item IDs and plan-only override isolation. Run shared/backend/native checks and form/scroll accessibility review. **Done:** server rejects forged relationships and no draft disappears on save failure.

**Acceptance:** existing item CRUD, atomic revisioned ordering, accessible moves, correct plan-only arrangement/key/sequence and honest unsupported fields.

**Handoff:** completed pass, shared contract changes, tested stale-write cases and the advanced timing/category slices still pending.
