# MOB-018 — Targeted email and device text handoff

Read [execution rules](../IMPLEMENTATION-RULES.md). **User story:** As a leader, I review the actual permitted recipients before sending an operational message or opening my phone's text composer.

**Read:** mobile spec communication section; US-09.2; [F09 prompt](../services-capabilities/F09.md) messages pass; [F00 prompt](../services-capabilities/F00.md) delivery records; native plan Teams/detail; backend notification/email services; shared people/notification/API contracts and directory privacy.

## Pass A — Targeted email

1. Implement/reuse the shared audience-preview/send contract: selected teams, scheduled/pending/signup audiences, deduped Persons, address readiness, exclusions, template variables and versioned audience snapshot. An organization invitation is a separate message type. **Done:** a preview performs no send and exposes no unauthorized contact fields.
2. Add native audience selection and a bounded composer with subject/body, allowlisted template variables and escaped rendering. Show the resolved recipient count, exclusions and missing addresses; only reveal details the leader may read. **Done:** the user reviews the exact permissible audience and content before explicit Send.
3. Submit an idempotent server command; recheck audience permissions/current resource state and require fresh review when the snapshot is materially stale. Deliver via F00's outbox and existing transport. Show queued/simulated/provider-accepted/failed per recipient as permitted. **Done:** a timeout/retry creates one logical message and never equates queueing with delivery.

## Pass B — OS text composer

4. Verify supported iOS/Android composer APIs and current Expo build requirements. Resolve a permitted phone-number audience, review disclosure to other recipients and offer a safe limited/single-recipient handoff when multi-recipient privacy cannot be maintained. Do not use carrier email gateways. **Done:** unavailable SMS capability/permission has a recoverable fallback, with no external message sent during tests.
5. Open the OS composer only after the user's explicit action, with minimum authorized content/link. Keep handoff/cancel/unknown outcomes distinct from app-delivered email; cancellation creates no sent record. **Done:** UI and history never assert that the external composer actually sent a text without supported evidence.
6. Test denied audience, membership change after preview, duplicate recipients, missing address, unsafe template input, transport failure/retry and canceled/unavailable composer. Run shared/backend/native checks and physical-device handoff tests when available. **Done:** scope/privacy and outcome semantics hold across both channels.

**Acceptance:** explicit audience review, permission-aware contact disclosure, safe templating, durable truthful email outcomes and deliberate OS text handoff. Inbound email ingestion and new SMS providers remain separate integrations.

**Handoff:** audience/transport contracts, tested failure cases and unverified physical-device behavior.
