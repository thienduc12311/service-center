# MOB-026 — General attachments, preview, upload and share

Read [execution rules](../IMPLEMENTATION-RULES.md). **User story:** As an authorized planner, I attach the correct materials to a plan, item, song, arrangement or key; as a participant, I open only files I may read.

**Read:** mobile spec attachments section; US-13.1/13.2; [F13 prompt](../services-capabilities/F13.md); native document songbook upload as a narrow pattern; shared file/API contracts, backend Storage policies and parent resource routes. General attachments are not the songbook document feature.

## Pass A — Shared file lifecycle

1. Verify/implement F13 primary owner, upload intent, bounded upload access, finalize/version, audience and authorized download contract. Key-specific ownership needs actual F15 key records, not a guessed string identifier. **Done:** both raw Storage reads and URL issuance deny an unauthorized participant.
2. Define permitted type/size limits, external link policy and file version behavior for each parent. Preserve pinned historical versions and separate songbook documents. **Done:** incompatible parent relationships and unauthorized audience expansion fail on the server.

## Pass B — Native picking and reading

3. Add permitted file/photo/link entry with explicit OS permission, cancellation and size/type validation. Upload via intent with progress/cancel/retry; finalize only after storage success, using idempotent operation identity. **Done:** incomplete/failed uploads are not exposed as ready attachments and orphan cleanup follows F13.
4. Render parent-scoped lists and supported PDF/image/audio/video/link previews. Renew expired access under current rights; show unavailable external formats clearly. Keep UI and playback ownership consistent with MOB-024. **Done:** preview opens the intended immutable version and expired URLs do not become permanent cache credentials.
5. Add deliberate OS share/download actions with minimal authorized payload, temporary-file cleanup and truthful cancellation. Explain that an external share leaves app-controlled access; do not create a delivery record for a canceled sheet. **Done:** restricted file rights control whether sharing/downloading is offered and server issuance agrees.
6. Test denied picker, canceled selection, too-large/unsupported file, interrupted upload, duplicate finalize, moved/foreign parent, expired URL, revoked membership and canceled share. Run backend/RLS/Storage tests plus native exports and supported device preview/share checks. **Done:** API and Storage evidence covers both metadata and bytes.

**Acceptance:** actual versioned upload lifecycle, organization/parent/audience enforcement, honest progress/error states, supported preview and explicit permitted sharing.

**Handoff:** supported parents/formats, rights/limits, Storage tests and remaining native SDK/device gates. Scanning/OCR and media-record creation are not implied.
