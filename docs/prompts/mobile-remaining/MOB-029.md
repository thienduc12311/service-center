# MOB-029 — Native Lyrics & Chords editor and PDF share

Read [execution rules](../IMPLEMENTATION-RULES.md). **User story:** As a musician with edit permission, I revise a chart on my phone and export the same key, notation and sequence that I preview.

**Read:** mobile spec chart editor section; US-11.2/15.3; F11/F15 selected contracts; native song screen/ChordChart; website ChartEditorPage, chart-editor components and `frontend/src/lib/chart-export/`; shared ChordPro, chart HTML/document and songbook helpers. Inspect native export compatibility rather than importing DOM-only web code.

## Steps

1. Trace the canonical chart representation, render options, sequence/key resolution and arrangement save API. Add expected revision if missing. Distinguish editing library source from a plan-only sequence/key override. **Done:** one typed editing context specifies owner, source revision and exact preview/export options.
2. Add a keyboard-safe source editor, section/sequence controls and shared-renderer preview, reusing validated chart formatting settings. Preserve dirty draft, explicit save/cancel and navigation review; unsupported transformations show a clear state. **Done:** source, selected sequence and rendered chords/labels agree after every supported change.
3. Save through shared validation/API with capability checks; handle stale source by offering review/refresh rather than silent overwrite. Retain drafts after network error, scope them to account/org/resource and clear them safely on sign-out. **Done:** a failed or denied save never discards text or transfers it to another context.
4. Define/extract a platform-neutral document model from the current canonical export pipeline where necessary. Implement PDF generation through a verified compatible native or authorized server adapter, preserving chord alignment, notation, key, sequence, copyright and permitted fonts. **Done:** web/native exports use the same document inputs; native does not pretend HTML text is a PDF.
5. Add preview and deliberate file share with temporary cleanup and permission-aware error/cancel behavior. Test real generated PDF pages, not just file existence. **Done:** actual PDF rendering remains aligned for long lines, page breaks, accidentals and alternative notation.
6. Add shared rendering fixtures and save/revision tests; compare equivalent native/web preview/PDF cases. Run common checks and native keyboard/selection/share tests on supported devices. **Done:** chart content equivalence is verified, with platform visual gaps recorded.

**Acceptance:** safe dirty-state editing, correct scope, shared chart semantics, actual readable PDF and truthful save/share states. Provider/OCR imports are separate decisions.

**Handoff:** editor ownership, export adapter/build needs, comparison fixtures and pending device/visual gates.
