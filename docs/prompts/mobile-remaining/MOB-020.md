# MOB-020 — Notification preferences and exact destinations

Read [execution rules](../IMPLEMENTATION-RULES.md). **User story:** As a volunteer, I choose useful notification types and badges, recover from OS denial and open the exact authorized destination.

**Read:** mobile spec push section; MOB-003 lifecycle/intent implementation; [F08 prompt](../services-capabilities/F08.md) preference/dispatch pass; F09 conversation mute; F12 run subscriptions; `mobile/src/providers/NotificationsProvider.tsx`, `mobile/src/lib/push.ts`, `mobile/app/notifications.tsx`; backend notification routes/model/Expo sender and shared notification schema.

## Steps

1. Inspect actual event/channel types and device ownership. Reuse MOB-003 session-bound cleanup and validated intents. Define persisted account/org/event/channel preferences with explicit defaults, plus local badge display preference. Distinguish app preference, conversation mute and OS permission. **Done:** one effective-policy resolver governs feed/push jobs without treating a disabled badge as disabled messages.
2. Add shared validation/storage/API and RLS if absent, loading the DB skill first. Recheck preferences at dispatch, not only when enqueuing; critical operational defaults must be explicit and editable where policy permits. **Done:** another Person cannot read/write preferences, and a queued message respects a later mute.
3. Add native settings for supported types/channels, badge choice and OS permission status with a deliberate “Open device settings” action. Do not repeatedly request denied permission or claim app toggles override the OS. **Done:** denied OS push still leaves an in-app feed and useful recovery path.
4. Resolve taps through typed organization/target intents for existing plans/threads/runs. Reauthorize after org switch, handle missing targets and consume initial taps once. Run pushes are opt-in for an active run; leaving ends the subscription. **Done:** stale taps never route to another user's cached resource or nonexistent chat infrastructure.
5. Apply badge rules from the active authorized context; clear on sign-out/account change. Validate lock-screen payload minimization and documented offline revocation limitations. **Done:** local UI does not advertise old-account unread data and server invalid registrations are excluded.
6. Test toggles/restart, queued-then-muted, OS denial, duplicate/cold-start tap, revoked target, session switch and leave-run. Use provider fakes and real-device tests only where available; run common checks. **Done:** persistence, dispatch and navigation evidence are recorded separately from bundling.

**Acceptance:** persisted preferences, dispatch-time enforcement, correct private destination, safe cleanup, clear OS fallback and truthful badge behavior.

**Handoff:** default matrix, effective policy, target types actually supported, tests and remaining push/device gates.
