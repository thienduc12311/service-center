# MOB-023 — Native Live viewer and controller

Read [execution rules](../IMPLEMENTATION-RULES.md). **User story:** As a service participant, I follow the authoritative current/next item; as a controller, I deliberately advance one service occurrence without conflicting with another controller.

**Read:** mobile spec Live section; US-12.1/12.2; [F12 prompt](../services-capabilities/F12.md); native plan workspace; F11 order/timing, F09 run chat and MOB-003/020 navigation/push. Notification polling is not the Live state engine.

## Pass A — Authoritative run integration

1. Verify/reuse F12 per-plan-time run snapshot, revision, server timestamps, controller lease and action endpoints. Implement missing F12 passes before native controls. **Done:** two service occurrences have independent run identity/history and a run pins its planned order version.
2. Define a native run-state adapter that hydrates current state, subscribes/polls through the actual supported transport and reconciles revision gaps by reloading. Calculate countdown from server time offset/transition timestamps; display ticks never write to the DB. **Done:** a reconnect returns to authoritative state without replaying local control gestures.

## Pass B — Viewer and control UI

3. Add an occurrence/run picker, current/next item, remaining/overrun, finish estimate and last-synced/connection indicator. Show only permitted notes/files and explicit stale state when offline/backgrounded. **Done:** viewers can distinguish live authority from cached display and zero-length headers do not start phantom timers.
4. Add capability-gated advance/pause/resume/jump/end and deliberate controller takeover. Review destructive jumps/end where appropriate; send expected revision/lease plus idempotency. Handle lost lease or conflict by refreshing, never claiming a local command applied. **Done:** simultaneous controllers yield one valid winner and a clear loser state.
5. Optional run chat uses F09; opted-in run push uses MOB-020. Leaving/switching run tears down listeners and push subscription; background return reloads before control. **Done:** no old run continues updating another plan or notifying after departure.
6. Test reconnect, clock skew, duplicate action, lease expiry, background/resume, plan edit during pinned run, two service instances and permission revocation. Run shared/backend concurrency tests plus native export and two-device checks when available. **Done:** both viewers converge and control/history evidence comes from server records.

**Acceptance:** authoritative independent runs, one valid controller lease, correct derived timers, safe stale/reconnect states and no hidden per-second persistence.

**Handoff:** transport/build requirements, tested actions and pending multi-device/background gates. Public stage display and advanced rebase/corrections are separate F12 stages.
