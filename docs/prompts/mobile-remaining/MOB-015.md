# MOB-015 — Edit plan times and team reminder policies

Read [execution rules](../IMPLEMENTATION-RULES.md). **User story:** As a planner, I change a service or rehearsal time with an impact preview and configure supported reminders without losing assignment or calendar identity.

**Read:** mobile spec planning section; Services F04/F08 and their [time](../services-capabilities/F04.md)/[reminder](../services-capabilities/F08.md) prompts; web `EditTimesModal.tsx`; native plan screen; shared plan/time schemas; backend plan/time, feed and notification paths; ADR 0002/0003.

## Pass A — Stable time editing

1. Inspect current plan PATCH: the baseline matches complete time lists by position. Complete/reuse F04 stable IDs, expected revision and impact contract before exposing reorder/delete propagation. Validate selected assignment-time relationships. **Done:** changing list order preserves time IDs and existing assignment/feed references.
2. Add a native editor for kind (service/rehearsal/other), name, local date, start/end and organization timezone. Reuse the canonical timezone parser; reject invalid/nonexistent DST times and resolve ambiguity explicitly. Preserve drafts on failure. **Done:** a device in another timezone saves the intended local occurrence.
3. Show affected people, selected-time/all-time assignments, responses, feed events and scheduled jobs before a material change. Commit the reviewed revision once, through F04/F08 invalidation/reschedule rules. Deletion of a required time requires an explicit supported resolution. **Done:** stale previews cannot commit silently and deleted times leave no orphan references/jobs.
4. Test reorder, insertion, deletion, midnight/DST, rehearsal conflicts, concurrent update and failed commit. **Done:** stable event UIDs/sequences and updated actual attendance intervals are verified with shared/backend/RLS tests.

## Pass B — Reminder controls

5. Reuse F08's persisted team/service-type policy and effective inheritance; implement its policy pass if absent. Add enabled/disabled, pending-response versus confirmed-service policy, offset, quiet-hour/frequency behavior and effective-policy summary. Do not run reminders from a phone timer. **Done:** UI reads back persisted policy and distinguishes inherited defaults from overrides.
6. Preview the resulting due times in organization timezone and truthful queued/simulated/accepted/failed history where permitted. Test response before dispatch, changed time, disabled policy and permission revocation against the shared worker. **Done:** obsolete jobs are suppressed, retries remain idempotent and the native policy screen matches web behavior.

**Acceptance:** all time IDs survive safe edits, impact is reviewable, required attendance and feeds/jobs update consistently, and reminders use durable F08 infrastructure. A basic editor pass does not complete reminder automation.

**Handoff:** completed pass, identity/impact evidence, policy inheritance and pending worker-deployment/device gates.
