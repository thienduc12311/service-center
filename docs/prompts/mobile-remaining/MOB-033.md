# MOB-033 — Native schedule/rehearsal widgets

Read [execution rules](../IMPLEMENTATION-RULES.md). **User story:** As a volunteer, I see a minimal current schedule/rehearsal shortcut and open the correct authorized screen without exposing another account's information.

**Read:** mobile spec widgets section; F03/F14 optional stages; implemented MOB-003, MOB-020, MOB-024 and schedule APIs; `mobile/app.config.js` and native build workflow. Widgets need native extension support, not a React screen styled as a widget.

## Pass A — One-platform feasibility

1. Select iOS WidgetKit or Android app widgets for the first pass and inspect current official documentation, Expo integration, entitlements/shared storage, update limits and signed build requirements. Spike the smallest extension displaying nonprivate fixture data. **Done:** actual extension build/install evidence or a precise platform blocker is recorded; JS bundling is not proof.
2. Define a minimal account/org/Person-bound snapshot with version, expiry and permitted destination IDs. Exclude prepared requests, private notes, tokens and unnecessary roster details. Decide lock-screen content and logout behavior explicitly. **Done:** snapshot format and native storage boundaries are reviewed against real platform capabilities.

## Pass B — Live data and safe navigation

3. Populate the snapshot only from authorized schedule/rehearsal contracts and refresh through supported background mechanisms. Respect OS update limits and show stale/expired state; JS need not stay alive. Any extension network credential must be narrowly scoped/short-lived and cleared on revocation. **Done:** restart/background tests show truthful data age without persistent privileged credentials.
4. Wire taps through validated MOB-003 intents; opening a response/rehearsal screen reauthorizes current membership and exact request version. Keep write actions inside a reviewed app flow unless a separately verified native action contract exists. **Done:** a stale widget cannot confirm an assignment or open another account's cached plan directly.
5. On sign-out/account change, stop authorized refresh, clear shared snapshot and request OS reload. Invalidate expired/revoked content on the next supported update, documenting OS/offline limits rather than promising immediate remote wipe. **Done:** subsequent app access is safe even when the OS temporarily displays an older rendered widget.
6. Test physical-device background/refresh, logout, account switch, revoked organization, expired snapshot and duplicate tap. Run native build/extension tests and common workspace checks. Add the second platform as a separately tracked pass only after the first works. **Done:** selected platform behavior has evidence and unsupported platforms remain explicit.

**Acceptance:** real native extension, minimal authorized snapshot, safe stale states, verified navigation and account isolation. A widget mockup or Expo export alone is not completion.

**Handoff:** platform/build feasibility, snapshot/credential policy, physical-device results and remaining second-platform gates.
