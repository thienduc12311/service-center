# MOB-012 — Plans browser and plan workspace

Read [execution rules](../IMPLEMENTATION-RULES.md). **User story:** As an authorized planner or scheduled volunteer, I find permitted plans by service type and open the same Order/Teams/Rehearse workspace used on the website.

**Read:** mobile spec planning section; F01 visibility; `mobile/app/(tabs)/_layout.tsx`, `mobile/app/plan/[id].tsx`, auth/query conventions; `frontend/src/pages/PlansPage.tsx`, `PlanDetailPage.tsx`; backend plan/service-type routes and shared list/detail API methods.

## Pass A — Browse permitted plans

1. Inspect existing list filters, pagination, draft visibility and membership rules. Reuse F01 access/preparation rules if present; extend a missing list/cursor contract in shared/backend rather than filtering an unauthorized full collection on-device. **Done:** list rows/counts reveal only the caller's permitted plans and never private prepared staffing.
2. Add a Plans tab or capability-aware navigation entry without breaking existing schedule/calendar/songbook routes. Provide service-type selection, upcoming/history, bounded pagination, refresh and deterministic date ordering. Persist only appropriate per-account/org filters. **Done:** browsing beyond one page is possible and switching organizations resets invalid selections.
3. Add previous/next within the authorized selected service-type/order context; support direct plan links that are outside a cached page. Show deleted/forbidden/offline states and a retry. **Done:** navigation resolves by stable plan identity, not a stale list array index.

## Pass B — Workspace integration

4. Structure the plan screen around Order, Teams and Rehearse labels consistent with web. Preserve all personal positions/times and chart context from MOB-002/004/005. Connect implemented staffing/player features, with clear supported empty states. Unimplemented actions stay out of production navigation until their contracts exist. **Done:** the workspace is usable with today's APIs without implying that native editing or playback already works.
5. Gate edit/create/release controls by effective capability; read access to a scheduled plan does not imply authoring. Retain pending/error state when changing tabs and restore scroll/context sensibly. **Done:** members can view authorized details while direct attempts at leader actions are rejected server-side.
6. Test pagination, equal service dates, deleted previous/next target, history, direct link, denied draft, team-limited leader and org-switch race. Run native checks and inspect phone/tablet, large text, screen readers and both themes. **Done:** browse and workspace navigation preserve authorization and existing routes.

**Acceptance:** bounded authorized browsing, stable previous/next, consistent workspace vocabulary, complete own-assignment context and no exposed unsupported actions.

**Handoff:** filters/pagination contract, navigation changes, role coverage and exact next editor task ready to consume this workspace.
