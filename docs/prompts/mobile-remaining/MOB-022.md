# MOB-022 — Calendar filters, subscriptions and report sharing

Read [execution rules](../IMPLEMENTATION-RULES.md). **User story:** As a volunteer, I filter my calendar, subscribe in my preferred calendar app and deliberately share an authorized plan report.

**Read:** mobile spec calendar/report section; US-16.2/16.3; [F16 prompt](../services-capabilities/F16.md); native calendar tab; shared calendar/feed client; backend calendar/calendar-feed/me routes; ADR 0002/0003; website CalendarPage and report/print helpers.

## Pass A — Filters and personal feed

1. Inventory supported mine/all, service-type/team/kind/date filters. Extend missing server filters as bounded typed parameters with authorization rather than downloading unauthorized rows. Display active organization/timezone and remember filters in the appropriate context. **Done:** screen results and visible counts agree with the server filter scope.
2. Add filter controls and preserve the native agenda. Use canonical selected attendance from F04 for personal entries; exclude prepared/private data. **Done:** a person scheduled only at 09:00 does not see an implied 11:00 commitment.
3. Reuse current feed creation/rotation APIs. Show raw URL only when returned at creation/rotation, avoid logs/query keys, and explain rotation invalidates the old subscription. Verify supported platform subscribe/copy actions against current docs. Preserve the deliberate confirmed-and-unconfirmed feed policy, not an assumed reference-only-confirmed policy. **Done:** subscribe/copy has a real supported fallback and invalid rotated URLs fail safely.
4. Test organization switch, denied filters, empty range, feed revocation and platform action cancellation. Explain that external calendar apps control polling. **Done:** app never promises immediate external sync or treats a copied link as verified subscription.

## Pass B — Plan report share

5. Implement/reuse F16 authorized generated plan report, including audience-safe notes, staffing and prepared exclusion. Request an actual report/version, show generation/error/expiry states, and preview before explicit OS share. **Done:** the report matches selected plan/filter context and contains no unauthorized fields.
6. Renew expired download access under current rights, then use supported file sharing with temporary-file cleanup. A cancelled share is not delivery. Test private fields, expired link, removed plan, failed generation and cancelled composer; run common checks and device handoff review. **Done:** file access/share remains deliberate and correctly scoped.

**Acceptance:** useful supported filters, secret-safe subscriptions/rotation, actual permitted report generation and honest OS handoff. Custom report design and shared feed administration stay on web initially.

**Handoff:** filters implemented, platform action evidence, report prerequisites and pending physical-device gates.
