# F15 — Library curation, structured import and arrangement keys

**Current status:** Read [the cross-feature audit](../../plans/services-mobile-contract-audit.md) and the latest [progress entry](../../plans/services-capabilities-progress.md) before choosing a pass. The steps below define scope; implemented passes are verification work, not a request to rebuild them.

Read [execution rules](../IMPLEMENTATION-RULES.md). **User story:** A planner finds and maintains songs without losing historical plans, and imports structured records only after reviewing mappings and row errors.

**Read:** Services spec F15; US-15.1/15.2/15.3; song/people routes/services, shared schemas/types, archive-related migrations, web Songs/People/SongDetail pages, chart/export helpers and current songbook uploads. OCR imports were removed; retained document upload is not parsing.

## Pass A — Filters, archive and bulk metadata

1. Inventory already implemented filters/archive APIs; extend actual missing key/BPM/tags/metadata/scheduled-date filters with bounded deterministic pagination and capability checks. **Done:** results beyond one page and metadata combinations are tested against real source projections.
2. Implement reversible song/arrangement archive/restore, picker exclusion and historical readability; preserve default arrangement rules. Add previewed atomic metadata/tag bulk edits with expected revisions/idempotency and audited row outcomes. **Done:** archive never breaks referenced plans/charts and a stale bulk row cannot silently overwrite newer work.

## Pass B — Structured people/song imports

3. Add import jobs/rows/provenance, bounded file/type limits, explicit column mapping, normalization, row validation/errors and duplicate-resolution choices. Preview performs no writes; isolate each organization's files and permitted fields. **Done:** user can inspect exact creates/updates/skips and unresolved rows before committing.
4. Commit the reviewed revision atomically within a bounded declared batch or as explicitly resumable tracked chunks. Recheck identity/access; match Persons by stable IDs or approved resolution, never merge accounts solely by email. Retrying the same job does not duplicate records. **Done:** forced failure/restart yields auditable recoverable results without hidden partial import.

## Pass C — Arrangements, labeled keys and optional merge

5. Add arrangement duplicate options with selected metadata/sections/files, new IDs and provenance through F13 link/copy rules. Model labeled key records under an arrangement with key/capo/vocal labels and scoped file associations. Keep plan-only overrides on items. **Done:** alternate key files can be selected without cloning or corrupting the source arrangement.
6. Duplicate-song detection/merge is a proposed optional convenience; implement only when selected. Preview all reference/history/default/key/file conflicts, then transactionally remap approved references and keep provenance/reversible history where feasible. **Done:** the loser cannot disappear before every approved historical reference remains valid.
7. Test archive/default/history, malformed/oversized CSV, duplicate rows, stale preview, foreign IDs, retry/chunk recovery, arrangement-file rights and selected merge rollback. Run shared/backend/RLS/web and affected native checks. **Done:** imported or curated data has the same invariants as normal authoring.

**Acceptance:** meaningful filters/archive, safe reviewed imports and independent arrangement/key scope. Provider catalog imports belong to F17; OCR restoration requires a new explicit decision.

**Handoff:** implemented stages, mapping/dedup semantics, transaction/chunk strategy, history evidence and optional merge status.
