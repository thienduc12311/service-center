# F16 — Attendance, operational reports, feeds and public projections

**Current status:** Read [the cross-feature audit](../../plans/services-mobile-contract-audit.md) and the latest [progress entry](../../plans/services-capabilities-progress.md) before choosing a pass. The steps below define scope; implemented passes are verification work, not a request to rebuild them.

Read [execution rules](../IMPLEMENTATION-RULES.md). **User story:** Leaders see trustworthy operational metrics and actual attendance; volunteers receive authorized calendar/print output; public sharing reveals only deliberately published fields.

**Read:** Services spec F16; US-16.1–16.4; F01/F04/F11 and F12 actual runs when present; backend calendar/feed/plan/song/assignment routes; web Dashboard/Calendar/MySchedule and print/PDF helpers; shared date/domain contracts; ADR 0002/0003. Native MOB-017/022 consumes the shared outputs.

## Pass A — Actual attendance

1. Persist present/absent/unknown per Person/plan-time occurrence, with actor/time/correction history, expected revision and scoped team authority. Deduplicate multiple positions at one occurrence; retain archive/history. Confirmation never implies present. **Done:** reviewed batch is atomic and competing leaders/forged team IDs are tested via API and direct SQL.
2. Build web marking/correction and read contracts for MOB-017. **Done:** a real leader can mark/correct without altering assignment answers, and reports reconcile to occurrence records.

## Pass B — Defined metrics and print/export

3. Define staffing/follow-up, participation/frequency/response history and song-usage metrics with explicit distinct-Person, assignment, Person-plan and song-occurrence versus distinct-plan rules. Date/service-type/team/status/draft/archive filters and organization timezone are recorded. Actual timing uses completed F12 runs only. **Done:** fixtures with two roles and repeated songs have unambiguous expected totals.
4. Implement bounded authorized report APIs and web filters, running-order/roster/multi-plan print plus CSV. Reuse canonical F11 chart/timing output, audience-safe note columns and CSV spreadsheet-formula escaping. Include generation time/filter/metric definitions. **Done:** screen, CSV and print reconcile and excluded prepared/private fields never appear.
5. Large exports use F00/F08 tracked jobs, access recheck and expiring F13-style result access. **Done:** revoked access prevents future retrieval and failed/retried generation is truthful/idempotent.

## Pass C — Calendar and publication extensions

6. Add scoped shared feeds and opt-in blockout/birthday/anniversary layers with current access and stable event identifiers. Preserve personal token rotation and product inclusion rules; external clients control refresh. **Done:** permission/token tests cover emitted fields and private dates are not inferred from profile metadata alone.
7. Add explicit sanitized plan/set-list publication with now/service-day scheduling, revocation and nearest-upcoming/most-recent links. Public data is an allowlisted projection excluding people/contact/private notes/files/chat by default. **Done:** unpublish/revoke and link resolution cannot expose the private parent or prepared staffing.
8. Optional custom report definitions use allowed columns/filters/group/layout, previewed under the actual viewer's access. No arbitrary SQL/script or definition-sharing-as-result-sharing. **Done:** saved templates cannot broaden source permissions.

**Acceptance:** actual attendance semantics, reconciled metrics/exports, stable scoped feeds and separately gated public/custom output. Test concurrency, privacy across all formats and actual document rendering; run relevant workspace checks.

**Handoff:** completed pass, metric definitions, source reconciliation, public/expiry policy and pending optional stages.
