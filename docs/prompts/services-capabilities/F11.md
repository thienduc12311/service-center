# F11 — Item editing, effective charts and running-order timing

**Current status:** Read [the cross-feature audit](../../plans/services-mobile-contract-audit.md) and the latest [progress entry](../../plans/services-capabilities-progress.md) before choosing a pass. The steps below define scope; implemented passes are verification work, not a request to rebuild them.

Read [execution rules](../IMPLEMENTATION-RULES.md). **User story:** A planner edits the actual service order and musicians see matching arrangement/key/sequence in rehearsal, print and mobile.

**Read:** Services spec F11; US-11.1/11.2/11.3; web OrderTab/AddItemModal/RehearseTab, chart components/export; backend plan item/order services; shared plan/song schemas and ChordPro/document helpers. Inspect MOB-002's context resolver/sequence contract before duplicating it.

## Pass A — Ordinary editing and chart correctness

1. Expose existing item update fields through an accessible web editor: title/type/length/description/song/arrangement/service key and plan-only sequence. Add revisioned atomic edit/reorder validation and same-org compatible references. **Done:** saved changes persist on existing item IDs and library defaults remain independent.
2. Implement/reuse one effective context resolver: authorized item arrangement, source key, plan display key, inherited/overridden sequence and viewing shift. Feed the same result to web/native rehearsal, chart label and print/PDF. Repair raw-source-versus-displayed-key mismatch wherever present. **Done:** a nondefault C-source arrangement in D produces D chords and label in every consumer, with no double transpose.
3. Provide accessible move controls, dirty/error/stale handling and deliberate remove. Test invalid arrangement, missing chart/key, overridden sequence and cross-plan leakage. **Done:** current single-plan editing improves without requiring advanced timing first.

## Pass B — Computed timing and responsibility

4. Compute planned item start/end/finish per selected service instance from explicit start plus durations; zero-length headers consume no time. Return derived schedule rather than persisting redundant timestamps. Add authorized print preview with selected note categories. **Done:** totals reconcile exactly and print uses the same timing/key context.
5. Add item leader as Person or plan-resolved team position, handling zero/multiple current assignees explicitly. Reuse F09 categories for permitted note columns and notify/report only allowed fields. **Done:** changing plan staffing changes position-based responsibility predictably without changing a direct Person leader.

## Pass C — Explicit advanced modes

6. Add pre/post sections, anchors, simultaneous groups, collapsible sections, applicability and F14 media links one selected mode at a time. Define timing before implementation: proposed simultaneous duration is max member length; contradictory anchors show gap/overlap, never silently shorten items. Keep actual F12 timing separate. **Done:** each enabled mode has deterministic calculation and warning fixtures.
7. Test reorder/edit races, duration edge cases, multiple service instances, leader ambiguity, private-note print and advanced mode calculations. Run shared/backend/web and affected native checks plus actual PDF visual inspection. **Done:** all consumer representations reconcile to the canonical item/order version.

**Acceptance:** usable editor, correct effective charts, stable revisions, computed timing and audience-safe responsibility/print. Optional timing modes remain separately labeled Service Center choices.

**Handoff:** completed passes, shared resolver consumers, timing rules, comparison tests and remaining advanced/device gates.
