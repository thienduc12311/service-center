# F12 — Authoritative Live runs and actual timing

**Current status:** Read [the cross-feature audit](../../plans/services-mobile-contract-audit.md) and the latest [progress entry](../../plans/services-capabilities-progress.md) before choosing a pass. The steps below define scope; implemented passes are verification work, not a request to rebuild them.

Read [execution rules](../IMPLEMENTATION-RULES.md). **User story:** A director controls one actual service run while viewers stay synchronized, and actual timing remains separate from the planned order.

**Read:** Services spec F12; US-12.1/12.2; F01 capabilities/F11 order timing; current plan services and shared contracts; web plan workspace and deployment configuration. Native [MOB-023](../mobile-remaining/MOB-023.md) consumes the same state/action transport.

## Pass A — Run model and serialized actions

1. Define run identity for one actual plan-time occurrence, pinned order snapshot/revision, visible state, controller lease, server timestamps and append-only transitions. Starting another service occurrence creates another run. **Done:** neither planned durations nor a prior occurrence's actual history is overwritten.
2. Implement scoped create/read/start/advance/pause/resume/jump/end and deliberate control transfer, using expected run revision, valid lease and durable action idempotency. Handle zero-duration headers explicitly. Read locking guidance; serialize state/transition updates in one transaction. **Done:** concurrent controllers yield one valid action and failed/replayed commands cannot duplicate transitions.
3. Derive countdown/finish from timestamps and selected visible policy, not one DB write each second. Pin plan edits during active run; MVP requires refresh before start or an explicit later rebase action. **Done:** clock-skew and changed-plan fixtures produce clear warnings and deterministic state.

## Pass B — Realtime and clients

4. Verify a compatible authenticated realtime/polling transport using current primary docs and deployment constraints. Authorize subscriptions, include revisions and reload on gaps/reconnect. Recheck revocation. **Done:** a disconnected viewer converges after reconnect and cannot retain a private subscription after losing access.
5. Build web viewer/controller with current/next item, remaining/overrun, finish estimate, connection freshness and explicit controls. Native follows MOB-023. Keep control conflicts and offline commands honest; no queued local gesture is represented as committed. **Done:** two clients agree from persisted authority and only the valid controller can act.

## Pass C — Selected extensions

6. Add run chat through F09, stage fullscreen, audited actual-time corrections and F16 planned-versus-actual reporting as separate slices. A public limited display requires explicit F16 publication and excludes people/private notes/files/chat by default. **Done:** corrections append actor/reason history and public projection has independent access tests.
7. Test controller expiry/transfer, duplicate action, jump/pause/end, header, restart/reconnect, two service instances, clock skew, plan-edit warning and revoked viewer. Use actual DB contention plus multi-client testing. **Done:** state/history and visible timers reconcile without per-tick persistence.

**Acceptance:** independent authoritative runs, one valid controller, durable actual history, safe reconnect and clear overrun policy. Public display and advanced rebase are not required for core Live completion.

**Handoff:** model/action contract, lease/transport behavior, concurrency/multi-client evidence and remaining deployment/device gates.
