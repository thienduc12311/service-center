# F13 — Versioned attachments and enforced file audiences

**Current status:** Read [the cross-feature audit](../../plans/services-mobile-contract-audit.md) and the latest [progress entry](../../plans/services-capabilities-progress.md) before choosing a pass. The steps below define scope; implemented passes are verification work, not a request to rebuild them.

Read [execution rules](../IMPLEMENTATION-RULES.md). **User story:** A participant retrieves the correct permitted file version while a planner uploads/replaces materials without exposing incomplete or private bytes.

**Read:** Services spec F13; US-13.1/13.2; existing attachments/bucket migrations, especially later policy changes; backend songbook upload and resource routes; shared database/API schemas; web parent workspaces. Native MOB-026/030/031 and F14 manifest consume this lifecycle.

## Pass A — Ownership and access model

1. Inventory existing metadata, object paths and raw Storage policies. Keep songbook documents distinct. Define exactly one primary owner (plan/item/song/arrangement, key after F15) plus explicit reuse links, category/audience and immutable version identity. Enforce valid same-org parent relationships in persistence. **Done:** every object/version has an unambiguous owner and authorized audience.
2. Implement policy evaluation for uploader, scheduled/team/position reader and scoped manager, including prepared visibility. Narrow existing broad bucket reads before promising restricted files. Apply access to raw object reads, metadata, upload/finalize and signed download issuance. **Done:** direct Storage tests prove excluded members cannot fetch bytes by guessed path.

## Pass B — Upload/finalize/download lifecycle

3. Add typed upload intent with bounded size/type/path/expiry, verified completion/finalize, orphan/failed state and safe cleanup. Repeated finalize is idempotent. Keep upload credentials scoped to the exact intent; check metadata against actual stored object. **Done:** partial/mismatched uploads never become ready files or overwrite another parent's version.
4. Add authorized short-lived download access, renewal under current rights, archive/version replacement and pinned historical links. Explain the bounded validity of already issued URLs; revocation cannot revoke copied bytes instantly. External URLs are validated and not server-fetched without a deliberate egress policy. **Done:** current rights govern new access and pinned plans retain the intended version without hidden audience expansion.
5. Build web lists/pickers/progress/preview/share for initial parents and expose shared API methods for native. Parent move/copy preserves explicit content/audience semantics and does not make a private reused file public. **Done:** a real user can upload, finalize, open and replace a permitted attachment with truthful failure states.

## Pass C — Defaults and documents

6. Add service-type default file links and permitted position/file tags, defining future-plan linking versus historical pinning. A simple text document editor creates a versioned attachment with allowlisted formatting/escaping. Labeled-key files wait for real F15 key records. **Done:** changing a default cannot silently rewrite historical preparation or broaden access.
7. Test foreign parents, raw Storage denial, unauthorized finalize, token expiry, interrupted/orphan upload, concurrent replace, reused audience, deleted owner and historical pinning. Run DB/RLS/Storage/shared/backend/web plus changed native checks. **Done:** tests cover bytes as well as metadata and client links.

**Acceptance:** complete lifecycle, exact ownership/version, matching API/Storage audience, recoverable upload and bounded authorized download. Existing table presence is not completion.

**Handoff:** ownership matrix, limits/TTL, rollout impact on current objects, actual Storage evidence and remaining cleanup/deployment gates.
