# F05 — Multi-plan Scheduling and order Matrix

**Current status:** Read [the cross-feature audit](../../plans/services-mobile-contract-audit.md) and the latest [progress entry](../../plans/services-capabilities-progress.md) before choosing a pass. The steps below define scope; implemented passes are verification work, not a request to rebuild them.

Read [execution rules](../IMPLEMENTATION-RULES.md). **User story:** A scheduler reviews and staffs several upcoming plans in one bounded view, without losing manual work or applying a partial hidden batch.

**Read:** Services spec F05; US-05.1/05.2; F01/F02/F04/F08 implemented services and F10 copy service; web PlansPage, plan TeamsTab/types/SchedulePeopleModal; backend plan/assignment services; shared API and staffing counts.

## Pass A — Read-only staffing workspace

1. Define bounded matrix queries, initially up to 12 plans plus a paginated Person roster, with service-type/team/date filters and deterministic ordering. Reuse canonical needs, answers, prepared/released visibility, assigned times, conflicts and recent serving metrics. **Done:** API projection exposes only authorized cells/counts and does not fetch every plan/person.
2. Build a web workspace with plans as columns and people/positions as rows, clear totals and empty/denied/error states. Add keyboard navigation/actions and accessible alternatives to dragging. Store named views per owner/org, validating filters after scope revocation. **Done:** a leader can compare permitted plans and restore a view without accessing another user's saved configuration.

## Pass B — Reviewed bulk staffing

3. Add explicit select/assign/remove/copy/release actions. Preview returns operation identity, base revisions, exact cells/people/times, conflicts/warnings and delivery intent. Copying never reuses answers or delivery timestamps. **Done:** preview performs no writes or sends and fully describes the declared transaction scope.
4. Implement one idempotent atomic commit through shared assignment/conflict/release services with consistent lock order and current capability checks. Recheck every candidate/plan/version; fail the declared batch on stale/invalid scope rather than silently skipping cells. **Done:** forced failure leaves no partial cells and duplicate commits return the original result.
5. Show a recoverable conflict review, preserve manual selections, and refresh only affected views after success. Keep prepare versus release distinct and explain partial outcomes only for explicitly separate operations. **Done:** no UI loop is labeled an atomic multi-plan action.

## Pass C — Order Matrix extension

6. After F10/F11 support atomic section/item copying, add a separate order comparison workspace for songs/keys/durations/sections. Preview destination append/replace scope and copy selected items with new IDs. Preserve destination roster/times unless explicitly selected. **Done:** order reuse never masquerades as staffing copy or changes unrelated destinations.
7. Test 12-plan bounds, pagination, scope filtering/count leaks, keyboard operations, stale middle cell, rollback, duplicate commit and concurrent staffing. Run shared/backend/RLS/web checks. **Done:** source rows reconcile to rendered cells and real transaction results.

**Acceptance:** bounded authorized comparison, accessible actions, atomic declared bulk scope, truthful conflicts and preserved manual/confirmed history. Order Matrix is a separate extension, not required for core staffing completion.

**Handoff:** passes complete, query bounds, atomic scope/lock policy, real concurrency evidence and remaining extension gates.
