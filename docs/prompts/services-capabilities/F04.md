# F04 — Assignment-specific attendance times and accurate conflicts

Read [execution rules](../IMPLEMENTATION-RULES.md). **User story:** A volunteer is assigned only the service/rehearsal times they must attend, and leaders see real overlaps rather than misleading whole-plan envelopes.

**Read:** Services spec F04; US-04.1/04.2; current plan-time PATCH, assignment routes/serviceWindow and scheduling_conflicts RPC; shared plan/assignment/date contracts; calendar/feed/ICS/notification rendering; ADR 0002/0003. Inspect MOB-005 Pass B before adding duplicate time storage.

## Pass A — Stable time identity and applicability

1. Replace positional time updates with stable IDs, expected revisions and a compatible legacy adapter. Model assignment mode all-applicable versus selected-time IDs; validate links belong to the same plan/org. Define added/deleted time behavior and genuinely untimed legacy fallback. **Done:** reorder preserves identity and every applicable attendance interval has an unambiguous source.
2. Implement time-edit impact preview/commit for assignments, request versions, jobs and feeds. Preserve calendar UIDs and manage sequence changes, including recipient-specific applicability. **Done:** a materially changed promise invalidates old previews without silently rewriting unrelated responses.

## Pass B — Shared conflict resolver and commit safety

3. Compare the union of actual half-open service/rehearsal/other intervals, with separate blockout, overlapping-commitment and preference-warning results. Exclude only the exact assignment being edited or an explicitly identical obligation; do not globally ignore same-plan collisions. Redact inaccessible details. **Done:** 09:00–10:00 plus 11:00–12:00 does not block 10:15–10:45, but Friday rehearsal overlap does.
4. Expose typed candidate/scope conflict checks with expected revision and permitted override/reason. All assignment writers recheck under a shared transaction/lock strategy for Person/time contention; manual override is capability-gated and audited. **Done:** two concurrent conflicting commits cannot both pass a stale client preview unnoticed.
5. Use one attendance resolver for schedule, personal response snapshots, email/ICS, feeds, reports and later signup/replacement capacity. Keep attendance commitment separate from actual present/absent records. **Done:** all outputs describe the same required times, with prepared visibility enforced.

## Pass C — Web/native compatibility and verification

6. Add web time selection/impact controls and adapt existing staff/schedule components. Native MOB-005/008/015 uses the same APIs. Show unsupported legacy fallback visibly instead of claiming precision. **Done:** web reload and shared client examples match actual stored scope.
7. Test adjacent intervals, overnight/DST, selected/all modes, new/deleted time, same-plan different position, foreign-time IDs, override permissions and real concurrent commits. Run SQL/RLS, shared/backend/web and affected native checks. **Done:** interval, identity, permission and invalidation promises have evidence.

**Acceptance:** stable times, exact attendance across outputs, meaningful redacted conflicts and commit-time race safety, with historical feed/token compatibility.

**Handoff:** time mode/deletion/fallback policy, shared resolver consumers, concurrency evidence and remaining migration gates.
