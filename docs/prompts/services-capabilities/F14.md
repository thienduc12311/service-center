# F14 — Rehearsal playlist, reusable media and stage preparation

**Current status:** Read [the cross-feature audit](../../plans/services-mobile-contract-audit.md) and the latest [progress entry](../../plans/services-capabilities-progress.md) before choosing a pass. The steps below define scope; implemented passes are verification work, not a request to rebuild them.

Read [execution rules](../IMPLEMENTATION-RULES.md). **User story:** A musician rehearses the plan's permitted materials in order; a leader can separately reuse media or a stage-layout snapshot when those extensions are selected.

**Read:** Services spec F14; US-14.1/14.2/14.3; F11 chart/order resolver, F13 versioned files; web RehearseTab/ChordChart and shared document helpers. Native MOB-024/025/027/030 are clients/stages of these shared capabilities.

## Pass A — Authorized manifest and basic player

1. Implement a bounded rehearsal manifest resolving item order, song/arrangement, effective key/sequence/chart, permitted file versions/types, stream/download rights and expiry. Audience evaluation uses current access, not file URL possession. **Done:** excluded/private files are absent and plan overrides match F11 output.
2. Build a minimal accessible web player with play/pause/seek/previous/next/repeat, chart/key/tempo and explicit external-link fallback. Use one playback owner and safe navigation/account cleanup; audio key is not claimed changed merely because chart key changes. **Done:** supported local fixtures play in order and errors do not silently skip to unauthorized media.
3. Expose the same manifest contract to MOB-024; verify current audio adapter/runtime docs at implementation. Test expiry, replacement, missing tracks, unsupported provider link and revoked rights. **Done:** manifest and playback state are coherent on web and shared/native callers.

## Pass B — Reusable media and stage layouts

4. Add media bundles with duration/creator/thumbnail/tags/themes/notes/files, usage history and optional archive date. Attach to actual media-capable order items, separate from songbook documents/songs. Provide web create/edit and native read-only consumption. **Done:** bundle links preserve file versions/rights and history.
5. Add an optional reusable stage-layout editor for people/gear/background, plan-specific snapshots and PDF export. Later staffing changes flag unmatched/departed Persons; refresh is deliberate. **Done:** layout coordinates/reference history survive a roster change without silently rearranging approved output.

## Pass C — Offline and advanced stage tools

6. Add explicit rights-aware offline manifest/cache policy, version/size/integrity/expiry and account cleanup, consumed by MOB-025. Document disconnected revocation limits. Audio transforms, PDF annotations/page turns, shared stage sessions and car/voice tools require separate feasibility/build/rights checks before the selected stage. **Done:** no stream-only content is implicitly downloadable and unsupported platforms stay gated.
7. Test audience/version/order resolution, user/org switch, archive/history, player interruption and selected extension behaviors. Inspect actual PDF/layout output and use physical devices for background/offline native claims. **Done:** basic playlist is demonstrably usable without depending on every optional stage tool.

**Acceptance:** authorized ordered materials, canonical chart context, working basic player and clear rights/fallback. Media/layout/offline/advanced stages have independent gates, not an implied full Music Stand clone.

**Handoff:** manifest/rights schema, playback evidence, selected extensions and pending SDK/device/rights decisions.
