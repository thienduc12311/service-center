# F10 — Saved templates, reusable sections and bulk plans

**Current status:** Read [the cross-feature audit](../../plans/services-mobile-contract-audit.md) and the latest [progress entry](../../plans/services-capabilities-progress.md) before choosing a pass. The steps below define scope; implemented passes are verification work, not a request to rebuild them.

Read [execution rules](../IMPLEMENTATION-RULES.md). **User story:** A planner reuses intentional templates and prepares several service dates without copying confirmations or corrupting existing destination plans.

**Read:** Services spec F10; US-10.1/10.2/10.3; F00 atomic copy, F04 time semantics, F08 preparation; `backend/src/services/plans.ts` and plan/setup routes; shared plan/service-type types; web PlansPage/PlanDetailPage/ImportTemplateModal. Native MOB-013 consumes the same preview/commit.

## Pass A — Templates and safe application

1. Distinguish service type, real scheduled plan, named plan template and reusable item/section template. Persist template revisions, chosen times/notes/order/needs and optional roster patterns with same-org references and provenance. **Done:** editing a template changes no already-created plan or response history.
2. Implement create/read/edit/archive templates and preview apply with explicit append/replace choices, exact selected components, warnings and destination revision. Reuse F00 atomic copy; optional roster patterns become prepared/unconfirmed with new IDs. **Done:** no preview writes and confirmed/delivery/run state is never inherited.
3. Add web template management and apply review, keeping existing duplicate/import paths compatible through the same service. Idempotency returns the same operation result; intentionally applying twice surfaces duplicate intent. **Done:** a failed copied child rolls back declared destination changes and stale revision requires review.

## Pass B — Bounded date generation

4. Define local-date series with IANA timezone, finite count/end, per-date edits and holiday exclusions. Resolve DST wall-clock intent explicitly rather than adding fixed week milliseconds. Preview every proposed plan/time/template revision. **Done:** four upcoming weekly plans preserve intended local time across DST and excluded dates are visible.
5. Commit atomically for the bounded initial batch or through an explicitly resumable job with durable per-plan state, aggregate status and idempotency. Recheck access/source revisions and avoid silent partial success. **Done:** timeout retry neither duplicates plans nor hides failed rows; each created plan has provenance.

## Pass C — Reuse/reschedule extensions

6. Add item snippets/sections, service-type defaults copy, plan series/title/artwork and bulk reschedule as individually tracked slices. A reschedule review distinguishes moving whole plans/times from copying order into a destination roster; lists affected responses/jobs/feeds and requires explicit response-reset choice. **Done:** no implicit answer reset, grant/person copy or historical template linkage.
7. Test stale source/destination, repeated application, wrong-org file/song/Person, missing needs, DST/date exceptions, forced rollback and resumable retry if used. Run real transaction tests and shared/backend/web/native compatibility checks. **Done:** source templates/plans and destination histories remain independent.

**Acceptance:** true saved templates, complete selected components, explicit apply scope, safe batch generation and preserved historical state. Core template use does not require every series/artwork extension.

**Handoff:** copied component matrix, transaction/batch strategy, timezone/provenance rules and remaining stages.
