# F03 — Availability, team preferences and delegated assistance

Read [execution rules](../IMPLEMENTATION-RULES.md). **User story:** Volunteers express reliable availability/preferences, and explicitly authorized helpers can act for a Person without receiving unrelated private access.

**Read:** Services spec F03; US-03.1–03.4; backend blockout/people/conflict routes and calendar; shared dates/Person/API contracts; web calendar/settings; [MOB-006](../mobile-first-10/MOB-006.md)/[MOB-007](../mobile-first-10/MOB-007.md) for detailed shared availability/preference steps. Reuse implemented F02 identity.

## Pass A — One-off and recurring availability

1. Inventory current timestamp-only create/delete behavior. Add compatible Person-scoped update, all-day/date intent, organization IANA timezone and revision checks. Use next-local-midnight exclusive bounds, not fixed 24-hour arithmetic. **Done:** different device zones and 23/25-hour days round-trip to the same intended dates.
2. Implement bounded weekly/monthly recurrence, end condition, preview and unique occurrence exceptions. Support web edit/delete of one occurrence, future occurrences or whole series, with explicit DST/month-end semantics. Reuse one resolver across previews, conflicts and storage queries. **Done:** no unbounded row expansion and replay/stale maintenance is safe.
3. Preview affected authorized commitments and offer a separate explicit decline action. Private reasons and prepared requests remain hidden from unauthorized audiences. **Done:** saving availability never silently changes an assignment response.

## Pass B — Preferences and freshness

4. Implement per-Person/team frequency, monthly maximum, preferred/avoided dates/weeks and selected-time preferences with documented unset/range/count semantics. Preferences produce typed warnings, distinct from hard blockouts. Count distinct served plans where that policy is used. **Done:** validated forms/API persist different team preferences without double-counting positions.
5. Add leader availability requests with scoped audience preview, durable jobs via F00/F08, freshness timestamps and response completion. **Done:** one retry sends one logical request and leaders can distinguish unknown/stale availability from an explicit blockout.

## Pass C — Explicit delegation

6. Persist grantor/delegate/target Person/organization, separate respond/view-plan/availability/signup permissions, expiry/revocation and audit. Adult grants require their explicit consent; a minor branch needs an established guardian policy before activation. Revalidate at every action. **Done:** household relationship alone grants nothing, and a response grant cannot fetch full private plans/files. Integrate [MOB-011](../mobile-remaining/MOB-011.md) against this contract.

## Pass D — Optional own-organizations aggregation

7. Add opted-in self-only combined schedules and explicit target selection for availability copying, reauthorizing each organization. Use immutable request context, bounded ranges and partial-failure reporting. Other schedulers see redacted blocked intervals, not another organization's titles. **Done:** tests prove tenant isolation and no new cross-org authority; [MOB-032](../mobile-remaining/MOB-032.md) consumes the same contract.

**Acceptance:** DST/recurrence integrity, private reasons, preference warnings, explicit grants and direct SQL/API revocation tests. Run shared/backend/web and affected native checks; optional stages remain separately recorded.

**Handoff:** completed pass, time/month policy, delegation decision gates, actual tests and next consumer.
