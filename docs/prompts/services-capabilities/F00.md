# F00 — Reliable delivery and atomic workflow operations

**Current status:** Read [the cross-feature audit](../../plans/services-mobile-contract-audit.md) and the latest [progress entry](../../plans/services-capabilities-progress.md) before choosing a pass. The steps below define scope; implemented passes are verification work, not a request to rebuild them.

Read [execution rules](../IMPLEMENTATION-RULES.md). **User story:** Administrators understand actual delivery outcomes and recover safe failures; planners never get a half-copied plan after an atomic operation fails.

**Read:** Services spec F00/shared invariants; US-00.1/00.2; backend `services/notifications.ts`, `notification-center.ts`, `email/resend-transport.ts`, `expo-push.ts`, assignment/public-response routes, `services/plans.ts`; backend config/startup/container/serverless entry points; shared notification/plan contracts and ADR 0001–0003. Existing transports, response links, feeds and ICS must be retained.

## Pass A — Outcome contracts and consolidated effects

1. Trace every assignment creation/response/notify path and provider result. Identify where console simulation is currently treated as success and where authenticated/public responses diverge. Define typed per-recipient/channel outcome and attempt/error records; distinguish queued, simulated, provider-accepted, confirmed-delivered where supported, failed and ambiguous timeout. **Done:** callers no longer need a misleading aggregate boolean/count to infer delivery.
2. Extract shared assignment-effect orchestration used by current writers, including scheduler decline updates and recipient grouping. Preserve exact existing response scope until F02/F04/F08 explicitly version it. Additive persistence and API responses retain old client compatibility. **Done:** one action produces one logical effect identity, whichever entry point executes it.

## Pass B — Durable execution

3. Add/reuse an outbox transaction boundary, leased bounded claims, stable semantic deduplication keys, attempts/backoff and terminal failure. Read DB locking/RLS guidance. Keep provider calls after commit and reconcile ambiguous outcomes with provider idempotency only where actually supported. **Done:** duplicate workers or a restart do not lose committed intent or duplicate logical records; external exactly-once delivery is never falsely promised.
4. Provide an authenticated bounded worker entry compatible with the actual container and serverless deployment patterns. Keep secrets/attempt internals server-only and recheck audience/eligibility at dispatch. Add admin outcome/retry UI using existing Settings/plan surfaces. **Done:** local invocation and restart recovery are tested; production scheduling remains an explicit deployment gate.

## Pass C — Atomic copy/apply foundation

5. Move selected item/time/notes/needs/optional staffing copy into one transaction with validated same-org parents, expected destination revision and durable idempotency. Reset copied answers, response/delivery timestamps and actual-run state. Reuse preparation state where implemented; do not describe `notify:false` as private. **Done:** a forced child-row failure leaves no partial destination mutation.
6. Preserve existing duplicate/import clients through compatible adapters and use this service in F10/F05 later. Test duplicate execution, rollback, wrong-org references, concurrent copy and partial provider failures. **Done:** existing single-plan workflows pass and source/destination histories remain independent.

**Acceptance:** honest outcomes, retryable durable effects, consistent public/authenticated response updates and atomic declared copy scope, backed by real transaction tests plus relevant workspace checks.

**Handoff:** passes implemented, outcome mapping, worker/transport limits, copy transaction evidence and remaining deployment gates. Coordinate with MOB-005 rather than creating a second outbox.
