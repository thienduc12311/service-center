# F08 — Request release, scheduled reminders and delivery history

**Current status:** Read [the cross-feature audit](../../plans/services-mobile-contract-audit.md) and the latest [progress entry](../../plans/services-capabilities-progress.md) before choosing a pass. The steps below define scope; implemented passes are verification work, not a request to rebuild them.

Read [execution rules](../IMPLEMENTATION-RULES.md). **User story:** A leader prepares privately, releases the reviewed request version and sends timely reminders that stop when no longer applicable.

**Read:** Services spec F08; US-08.1/08.2/08.3; F00 outbox, F01 visibility, F02 Person and F04 attendance; backend assignment/token/notification services, config and deployment entries; shared schemas/client; web staffing/public RespondAssignmentPage; ADR 0001–0003. Inspect MOB-005 Pass C/D before adding storage.

## Pass A — Exact request versions and release

1. Reuse/add snapshots of exact Person/plan assignment/time scope and expected versions. Migrate outstanding hashed single-use links to explicit scope or safely reissue ambiguous ones; never answer newly added rows through an old token. Make response/history/token consumption/effect intent atomic. **Done:** concurrent/replayed/stale public and authenticated responses have deterministic safe outcomes.
2. Implement scoped release preview/commit and scheduled initial release, distinct from publication and send transport. Hide prepared content across every recipient output. Consolidate multi-plan batches per recipient while retaining separately labeled plan-specific response actions. **Done:** review equals release scope, duplicate release is idempotent and one plan action cannot answer every plan in the email.

## Pass B — Policies and durable due work

3. Add service-type/team policy inheritance, explicit channel preferences, quiet hours and frequency caps. Proposed Service Center defaults are one pending-response reminder 72 hours before first applicable service and one confirmed-service reminder 24 hours before first applicable attendance; both editable/disableable. Display actual effective policy. **Done:** default/inherited/override behavior and timezone offsets are tested, not inferred from reference branding.
4. Plan durable jobs with semantic key including recipient/request version/policy/occurrence/channel. Claim with leases through F00's worker, bound each run and survive restarts. Before provider handoff recheck membership/Person, release, response, applicability/version, expiry and preferences. Material plan/answer/archive changes cancel/recompute jobs. **Done:** a response committed before dispatch suppresses the obsolete response reminder; two workers cannot enqueue distinct duplicate logical jobs.
5. Retry with backoff/terminal failure and record ambiguous provider timeout honestly. Use provider idempotency where supported; external delivery remains at-least-once otherwise. Fresh resends preserve usable scoped-link continuity until a replacement is durably issued. **Done:** retry/restart neither widens scope nor silently destroys the recipient's only usable action.

## Pass C — Policy/history clients and operations

6. Add web release review, schedule/policy controls and per-Person/channel history/retry, with native consumers MOB-005/015/020. Expose queued/simulated/accepted/delivered-when-known/failed correctly. Provide a protected bounded worker invocation/deployment guide matching actual hosting, without installing a speculative provider. **Done:** local/fake-clock end-to-end flow and restart recovery work; production scheduler configuration is a recorded gate.
7. Test quiet-hour DST, deadline/time change, response after enqueue, policy disable, membership revocation, duplicate worker, stale token and failure/retry. Run SQL/RLS/concurrency plus relevant client checks. **Done:** no obsolete audience/content leaks through delayed jobs.

**Acceptance:** private preparation, exact scoped answers, explicit release, durable revalidated reminders, honest delivery and compatible outstanding tokens.

**Handoff:** policy defaults/inheritance, request migration, dispatch guarantees/limits, tests and deployment gates.
