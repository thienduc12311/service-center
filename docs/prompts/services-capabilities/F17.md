# F17 — Selected providers, licensing and external developer access

**Current status:** Read [the cross-feature audit](../../plans/services-mobile-contract-audit.md) and the latest [progress entry](../../plans/services-capabilities-progress.md) before choosing a pass. The steps below define scope; implemented passes are verification work, not a request to rebuild them.

Read [execution rules](../IMPLEMENTATION-RULES.md). **User story:** An organization connects one useful external service with auditable permissions/imports, and can revoke it without exposing credentials or confusing scheduled use with licensed reporting activity.

**Read:** Services spec F17; US-17.1–17.4; selected provider references in the research register; existing config/secrets/Resend adapter patterns, F01 capabilities, F00/F08 jobs, F13 file rights and F15 import/provenance. A CCLI field or first-party REST endpoint is not an integration entitlement.

## Pass A — Choose and verify one contract

1. Select one named stage: B licensed catalog/usage, C product/media/presentation handoff, or D external developer API/webhooks. If no provider/use case is selected, finish an options/feasibility note with current primary documentation and bounded choices before asking for the missing decision. **Done:** owner, actual use case, provider access/scopes/commercial permission/rights, test environment, limits and revocation behavior are explicit.
2. Verify current official API/auth/reporting documentation and distinguish provider facts from assumptions. Avoid estimates or a working-connection claim before access can be verified. Design against fixtures when credentials are unavailable and record live verification as pending. **Done:** selected contract has versioned input/output examples and precise external gates.

## Selected stage

3. **B — Catalog/licensing:** implement server-side minimal-scope connection, access check, bounded search/preview and explicit import through F15/F13 with provider IDs/provenance. Track permitted file/license activity separately from scheduled song use. Manual/automatic copyright reporting requires verified provider-specific semantics and deduplication. **Done:** repeated import/report cannot double-create content or assert rights from metadata alone.
4. **C — Specific handoff:** implement one chosen People/Calendar/Check-Ins/media/presentation use case with explicit source of truth, field mapping, preview/commit, conflict policy, idempotent sync, rate-limit recovery and reconnect/revoke UI. Attendance adapters write actual attendance with provenance, not confirmation. **Done:** retries and partial failures reconcile without cloning an entire external product.
5. **D — External API/webhooks:** issue hashed/revocable scoped credentials, versioned typed schemas/pagination and rate limits matching F01 tenancy. Webhooks have event IDs, signatures/timestamps, replay controls, outbox retries and destination validation/egress policy. Keep first-party auth unchanged. **Done:** revoked credentials and forged/replayed delivery fail, and a subscriber cannot access unrelated org data or private events.

## Verification and operations

6. Encrypt provider secrets server-side, restrict service access, redact logs and define disconnect cleanup while preserving historical provenance/rights constraints. Add administrator outcome/retry/reconnect UI; no secret reaches shared client DTOs. **Done:** revocation prevents new sync/delivery and failed jobs do not expose credentials.
7. Test authorization, duplicate/timeout, rate limit, stale mapping, revoked token, bad signature/destination and unsupported entitlement using fakes plus selected provider sandbox where available. Run DB/RLS/shared/backend/web checks and affected native checks. **Done:** evidence distinguishes fixture integration, sandbox verification and production readiness.

**Acceptance:** one explicitly chosen end-to-end adapter or API stage, verified external contract, safe credentials, reviewed operations and revocation. Other providers/stages remain unselected; paid-product availability is not assumed.

**Handoff:** selected stage/provider, source links, rights/access evidence, implemented behavior/tests and exact external decision/credential/deployment gates.
