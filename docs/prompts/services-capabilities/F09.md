# F09 — Audience-safe notes, targeted messages and conversations

**Current status:** Read [the cross-feature audit](../../plans/services-mobile-contract-audit.md) and the latest [progress entry](../../plans/services-capabilities-progress.md) before choosing a pass. The steps below define scope; implemented passes are verification work, not a request to rebuild them.

Read [execution rules](../IMPLEMENTATION-RULES.md). **User story:** Leaders share the right operational details with the right people, review message recipients and discuss plans without leaking private notes/history.

**Read:** Services spec F09; US-09.1/09.2/09.3; F01 access/F00 effects/F08 delivery; plan notes and notification routes/services; web EditNotesModal/PlanSidebar/TeamsTab; shared contracts. F13 supplies attachments; native MOB-016/018/019 consume these APIs.

## Pass A — Categorized notes and item discussion

1. Preserve the current simple notes string through a compatible transition; add plan/item note categories, author/revision and explicit permitted audience. Enforce same-org parents and audience in RLS/projections, exports, search and notifications. **Done:** private notes cannot be obtained via raw reads, joined counts or generated documents by excluded users.
2. Add item comment threads with safe text/formatting, stable message IDs, pagination, mentions and actual thread membership. Resolve mention recipients under current access before creating effects. Provide web add/edit/delete where policy permits, with audit. **Done:** mentions do not grant access and retry yields one logical comment.

## Pass B — Targeted operational messages

3. Implement audience preview from permitted teams/scheduled/pending/signup Persons, deduplication, missing-address/exclusion list and a versioned recipient snapshot. Add allowlisted escaped template variables. Preview sends nothing; stale material audience changes require review. **Done:** sender can inspect the actual allowed content/audience without private-field escalation.
4. Persist explicit Send idempotently through F00/F08, per-recipient outcomes and authorized history/retry. Current membership rechecks govern future delivery/read access without silently rewriting historical recipient records. Preserve scheduler Reply-To; arbitrary inbound-email ingestion is separate. **Done:** failures are recoverable and no queued/simulated attempt is called delivered.

## Pass C — Team/plan conversations

5. Add conversation/membership, paginated messages, stable send IDs, unread/read state, mute, search and a real report/moderation path. Define retention and current team/group limits. Realtime/push recheck scope after membership change; run chat uses this service with F12 scope. **Done:** revoked users cannot continue reading through an old subscription or cached authorization.
6. Implement basic web thread/composer and expose the same contracts to native. Attach files through F13. Keep DMs, rich social features and youth/guardian-sensitive branches gated until an explicit organizational policy and moderation behavior exist; do not infer a rule from inconsistent external age text. **Done:** every enabled type has enforceable participants/content/report rules.
7. Test private-note output leaks, forged parent/category IDs, audience-change race, unsafe variable input, lost acknowledgement, duplicate message, paginated history and revoked realtime membership. Run RLS/backend/shared/web and affected native checks. **Done:** actual source, byte access and delivery paths respect the same audience.

**Acceptance:** safe categories/threads, explicit reviewed sends, durable truthful outcomes, authorized conversation history and meaningful moderation. Optional rich communication remains separately tracked.

**Handoff:** supported message types, policies, audience/version semantics, realtime evidence and remaining policy/device gates.
