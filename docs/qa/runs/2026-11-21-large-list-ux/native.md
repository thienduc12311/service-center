# Large-list UX on iOS

Tested on an iPhone 17e simulator running iOS 27.2 and Expo Go 57.0.9. Metro ran on port 8091 and the local API on port 4711. The English UI used a synthetic bilingual library of 174 active songs, 257 people, and 20 teams. The Worship Band fixture had 40 members and 12 positions. Changes to the plan order used a new draft named **QA Native Large List**.

| Flow | Result | Evidence |
| --- | --- | --- |
| Plans title search | Typing `Native Large` narrowed Upcoming to the newly created draft. Its row opened the plan. | [Plans search](evidence/native/plans-title-search.png) |
| Add Songs views and paging | Suggested showed usage metadata. All A–Z started with the alphabetical first page and loaded the next page on scroll, including `Cornerstone (Live)` and `Counting Stars (Live)`. Search, views and filters remained at the top. | [Suggested](evidence/native/song-browser-suggested.png), [All A–Z](evidence/native/song-browser-all.png), [page two](evidence/native/song-browser-page-two.png) |
| Accent-insensitive song search | From page two of All A–Z, typing `chua` returned to the first matching row, `Bình An Của Chúa (Live)`. The previous build had kept the old scroll position and shown matches from the end of the list. | [Search after scrolling](evidence/native/song-browser-accent-search.png) |
| Song filter sheets | Key, Tempo, Theme, and Type stayed visible at 390 pt after moving the filters to their own row. Key opened to the key grid and selecting C applied the chip and narrowed the rows. Tempo, Theme, and Type opened the expected choices. | [Key](evidence/native/song-filter-key.png), [Tempo](evidence/native/song-filter-tempo.png), [Theme](evidence/native/song-filter-theme.png), [Type](evidence/native/song-filter-type.png) |
| Insert songs after a plan item | The Move to sheet offered **Add songs after this**. Adding two songs in succession kept the browser open and updated the header to **2 added**. Done returned to the order. The API confirmed **Welcome**, **Tôn Vinh Danh Chúa**, **Tôn Vinh Danh Chúa Acoustic**, **Teaching**, in that order. | [Move to sheet](evidence/native/insert-after-sheet.png), [two added](evidence/native/song-browser-two-added.png), [saved order](evidence/native/insert-after-order.png) |
| Edit item and Change song | Typing `chua` returned the same accent-insensitive matches in compact rows with author and key. Opened from a song item that retained its existing arrangement. | [Change song](evidence/native/change-song-accent-search.png) |
| Schedule People pickers and scope | A searchable team sheet opened for 20 options. Searching for Worship narrowed it to Worship Band. Choosing it selected **Team members (40)** by default alongside **Everyone (257)**. Position opened a searchable sheet with the 12 named positions. | [Team sheet](evidence/native/schedule-team-picker.png), [scope counts](evidence/native/schedule-team-scope.png), [position sheet](evidence/native/schedule-position-picker.png) |
| Schedule People selection | Selected **Bình Hoàng** and typed `hannah` without refocusing the search field. The selection chip and **Schedule 1** action remained visible when the rows narrowed to two people. Switching to Everyone added two more matches and preserved the chip and action. | [Team search and selection](evidence/native/schedule-pinned-search.png), [Everyone search and selection](evidence/native/schedule-everyone-search.png) |

The simulator used hardware keyboard input. The blue gear in the screenshots belongs to Expo Go. Schedule People was tested through selection and review. Sending assignments and Android layout were outside this pass.
