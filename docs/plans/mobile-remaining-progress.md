Revision/idempotency: the message id is the idempotency key (no separate key). A draft (`id`, text, mentions, reply target) is kept in memory per user × organization × session generation (`conversation-drafts.ts`, never on disk) and survives leaving the thread; its id changes only after the server confirms it (or replays it) or on `message_id_conflict`. After no answer the thread is re-read: if the draft's id is already there it is treated as sent ("Your earlier message did arrive"); text edited after an unanswered send keeps the text with a fresh id.
